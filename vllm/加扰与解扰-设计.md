# 加扰与解扰 · 设计

## 1. 定位

边云协同推理跨节点搬运的中间激活值（`[token 数, hidden 维度]`）是模型中间层的真实输出，裸奔在网络上有被旁路采集、落盘、误读的风险。本模块在**发送前**加扰、在**接收后**还原，使这些字节不再是可直接读出的 bf16/fp16 明文。

三条硬约束：

1. **严格无损** —— 解扰后与加扰前**逐 bit 相同**，下游 attention / MoE 无感。
2. **seed 不上线** —— 两侧各自用同一组因子派生同一个 seed，seed 本身不跨节点。
3. **独立叶子** —— 不 import vLLM / 边云 / 通信层 / 调度器；只依赖 stdlib，torch 延迟导入。

> **不是密码学加密**：因子在控制面明文同步，掌握因子即可复算 seed。定位是"传输态混淆 / 防误读"，不挡掌握因子的攻击者。

## 2. 模块内容

### 2.1 对外接口

```python
class PayloadScrambler:
    def __init__(self, *, device_id: str, custom_factor: str) -> None: ...
        # 只做规范化 + 非空校验；两个静态因子由调用方从配置读出后传入

    def seed_for(self, *, client_ip: str, session_id: str,
                 conv_count: int) -> int: ...
        # 五个因子 -> 64 bit seed（纯函数、确定性）

    def scramble(self, t: Tensor, *, seed: int) -> Tensor: ...
        # 就地加扰，返回 t 本身

    def descramble(self, t: Tensor, *, seed: int) -> Tensor: ...
        # 就地解扰；与 scramble 同一实现（XOR 的逆元是自身）
```

公开面**一个类、三个方法**，无全局状态、无开关。

### 2.2 因子与 seed

| 因子 | 类型 | 来源 | 规范化 |
|---|---|---|---|
| `device_id` | str | 配置（构造时传入） | `strip()` |
| `custom_factor` | str | 配置（构造时传入） | `strip()` |
| `client_ip` | str | 每请求，动态 | 去端口 → IPv6 压缩 + 小写 → 取 `X-Forwarded-For` 最左一跳 → 非法降级 `0.0.0.0` |
| `session_id` | str | 每请求，动态 | `strip()` |
| `conv_count` | int | 每请求，动态 | 非负；非法 / 负 → `-1` |

- 因子顺序固定：`device_id → custom_factor → client_ip → session_id → conv_count`，各段以 `\x1f` 分隔。
- 派生用 **blake2b**，`person=` 做域分离、domain 串做版本域；**禁用内置 `hash()`**（受 `PYTHONHASHSEED` 逐进程加盐，两侧必然不同）。
- 两侧各自跑**同一函数 + 同一输入** ⇒ seed 逐位相同，构造上成立。

### 2.3 算子

- 把 16 bit 浮点 `view(torch.int16)`，与 `seed & 0xFFFF` **逐位异或**（就地）。
- **为什么不是"加 seed"**：bf16/fp16 浮点加法不可逆（加一个稍大的数就抹掉有效低位，减回来也回不到原值）；异或逐位独立、无进位、逆元是自身，**与平台无关的严格无损**。
- 只处理 `bfloat16` / `float16`；其余 dtype 抛错。就地、零额外内存。

### 2.4 校验与不可变性（best practice）

| 项 | 做法 |
|---|---|
| fail-fast | 静态因子为空 → 构造即抛；`seed` 非 int / 是 bool → 抛；dtype 非 16 bit → 抛；非连续张量 → 抛并提示 `.contiguous()` |
| 关键字-only | 三个动态因子与 `seed` 只能按关键字传，防"位置写错 = 用错 seed" |
| 不可变 / 线程安全 | frozen dataclass，构造后零写入；seed 派生是纯函数 → 多线程并发读安全 |
| 单一职责 | 只做"向量 + seed → 向量"；不读配置、不读文件、不碰网络 |

## 3. 上下文关系

```
调用方（worker / 通信层）                      本模块（叶子）
  ① 读配置 -> PayloadScrambler(device_id, custom_factor)
  ② seed_for(client_ip, session_id, conv_count)   ──▶  stdlib + hashlib
  ③ scramble(tensor, seed=seed)                   ──▶  （torch 延迟导入）
  ④ descramble(tensor, seed=seed)
```

- 依赖方向**单向**：只有"调用方 → 本模块"；本模块不 import 项目内任何代码。
- `seed_for` 不依赖 torch，可脱离 GPU 单独测试。

## 4. 被调用处（与需求一致，共 4 处）

| # | 时机 | 调用 | 说明 |
|---|---|---|---|
| ① | 进程启动 | `PayloadScrambler(device_id=…, custom_factor=…)` | 静态因子从配置读出，**在构造这里**传入 |
| ② | 每个请求 / 每个 flight | `seed_for(client_ip=…, session_id=…, conv_count=…)` | 动态因子来自请求 |
| ③ | 发送激活值**前** | `scramble(tensor, seed=seed)` | 就地；建议作用于通信层自己的副本，不改模型张量 |
| ④ | 接收激活值**后、使用前** | `descramble(tensor, seed=seed)` | 与发送侧同一个 seed |

## 5. 调用方注意

1. **一对 seed 一个矩阵**：`scramble` / `descramble` 只接受一个 seed。若一个 batch 混了多个请求（不同 `client_ip` / `session_id`），由**调用方**按请求切分后逐段调用；模块不感知 batch。
2. **因子两侧一致**：五个因子任意一个在两侧取值不同 → 解出垃圾且不报错。静态因子一致性靠部署保证，动态因子靠控制面同步。
3. **成对与顺序**：解扰必须用与加扰完全相同的 seed，同一段数据不可重复加扰。
4. **不是加密**：需要真正机密性时，应上预共享密钥 + 每次传输 nonce（乃至 AEAD），那是另一个量级。
