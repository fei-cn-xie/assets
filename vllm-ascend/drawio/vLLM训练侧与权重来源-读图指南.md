# vLLM 训练侧与权重来源 · 读图指南

配套文件：`vLLM训练侧与权重来源.drawio`（10 页）。
定位：**补上「权重从哪来」这一环**。前面八套讲的全是推理，这一套讲训练、量化、checkpoint，
以及训练与推理**真实存在**的那三个接口。

---

## 1. 十页清单

| 页 | 讲什么 | 一句话结论 |
| --- | --- | --- |
| ① | 训练与推理的边界 | vLLM 不做训练（0 处 backward/optimizer/DataLoader/train()），但共享结构、权重格式、配置 |
| ② | 一次训练 step 的九步 | 推理只保留四步，砍掉损失/反向/更新/清梯度 |
| ③ | 损失与 logits | 输出是「词表上的分布」；推理挑一个，训练用 −log p(正确词) 打分 |
| ④ | 显存账对照 | 训练四件套（权重+梯度+优化器+激活）vs 推理三件套（权重+KV+激活峰值） |
| ⑤ | 激活与 workspace | 训练的激活是「账本」，推理只要「峰值」；峰值随 token 上限线性涨（288 MB→6 GB 例） |
| ⑥ | 精度 | 训练要高精度主权重才能累积微小更新；推理整份 bf16，只有输出头被特意提到 fp32 |
| ⑦ | 量化 | 更少的位 + 一把尺子；粒度四档；本仓全是 PTQ 产物 |
| ⑧ | MTP 的两种命运 | 训练期多学一个「往后看」的目标，推理期当便宜的起草者 |
| ⑨ | 加载器挑文件 | 训练目录里五个文件被明确丢弃；名字映射「映射成 None」就是丢弃 |
| ⑩ | 真实接口：RL 后端 | 权重同步 / 暂停继续 / 逐层热更新 / 休眠让卡 + 三个一致性开关 |

三条路径：

- **只想懂差异**：① → ② → ④ → ⑤
- **要读加载/量化代码**：⑨ → ⑦ → ⑧
- **要接 RL 训练**：⑩ → ⑥（fp32 头）→ ⑨（热更新）

## 2. 一页纸答案

**vLLM 做训练吗？不做。** 四条证据：全仓 0 处 `loss.backward`、0 处 `AdamW`、包内 0 处 `DataLoader`、
0 处 `model.train()`（只有 `model.eval()`）；并且第三方算子文件里有一句原话：
「vLLM is inference-only so there is no backward pass」。

**但它有三块与训练打交道的代码**：
1. **运行时权重同步**（`weight_transfer`）——跑在**训练进程侧**的客户端，把新权重推给推理引擎，
   配 RLHF HTTP 路由（暂停 / 初始化 / 开始更新 / 结束）；
2. **为训练-推理一致性加的推理开关**——fp32 输出头、返回采样掩码、返回 MoE 路由；
3. **对训练产物的丢弃与兼容**——五个训练状态文件按文件名过滤、多余的键按「映射成 None」丢弃。

**训练与推理的三个接口**：权重文件（含量化描述）、配置字段（训练期字段被忽略）、RL 场景下的运行时权重同步。

**显存的本质差别**：
训练 = 权重 + 梯度 + 优化器状态 + 激活账本（会花 3~4 倍参数量的额外显存）；
推理 = 权重 + KV cache + 激活峰值（梯度与优化器全省了，改花在 KV 上换并发）。

## 4. 三个最容易搞错的点

1. **「vLLM 里没有训练代码，所以训练与它无关」**——错。它有一整套为 RL 准备的运行时权重同步；
   只是它自己不做梯度。
2. **「MTP 是训练技巧，推理无关」**——错。同一个头训练期学「往后看」，推理期当 drafter；
   两半靠 config 里一个「unused at inference」字段与一份键名映射分开。
3. **「量化是推理引擎做的」**——错。本仓 18 个量化方案全是**加载已量化 checkpoint**，
   没有任何伪量化/QAT 能力；量化本身发生在离线工具（ModelSlim 等）里。

---

## 5. 本仓实测：量化只在一个包里出现

- 十个部署包中**只有 1 个包**（`fix_1120`，DeepSeek-V4-Flash）带 `--quantization ascend`，
  模型目录名里直接写 w8a8；
- **0 个包**设置 `--kv-cache-dtype` → 其余包的 KV cache 仍是模型精度（bf16）；
- 该包唯一显式给的 KV 侧开关是 `indexer_kv_dtype: int8`，
  **它管的是 DeepSeek-V4 索引器侧的小 K cache，不是主 KV** → 主 KV 容量没变；
- 其余包（Qwen3.6-27B）全部 bf16，无量化。

三份并行只读走读：

1. **vllm 仓的训练痕迹盘点**：grep 全仓确认「无训练循环」，并逐条排除 6 类「貌似训练」的命中

2. **训练侧数学与显存**：推理侧的会计口径、workspace 算术、dtype 规则、量化粒度判据、
   `mtp_loss_factor` 与键名映射、checkpoint 黑名单；
3. **昇腾量化与权重格式**：`--quantization ascend` 的真实含义（选 ModelSlim 后端并读量化描述）、
   18 个 scheme、额外张量与名字映射表、ND→NZ 重排（含首次 15–19 s 的 lazy init）、
   KV 双旋钮（主 KV vs 索引器 K cache）、PTQ-only 的结论。
