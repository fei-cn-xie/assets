配套文件：`Transformer与模型文件结构.drawio`（21 页）。
目标读者：**有线性代数基础、但没有机器学习/深度学习背景**。
每页的编排都是同一条：**先给结论 → 再用大白话类比 → 最后给真实代码锚点**。

> 锚点说明：本机 Python 里没有装 `transformers`，所以锚点全部落在**本仓真实存在的
> vLLM 代码**上（`vllm/model_executor/...`），行号按当前检出分支核准。

## 1. 21 页清单

| 页 | 讲什么 | 一句话结论 |
| --- | --- | --- |
| ① | 总览 | 查表 → 矩阵乘 → 加权求和 → 再矩阵乘，重复 32 次，最后在词表上打分 |
| ② | 分词 | 文本 → token → 整数 id；BPE 是「统计出来的切法」 |
| ③ | 词嵌入 | id → 一行浮点向量，**查表不是乘法** |
| ④ | 位置编码 RoPE | 按位置**旋转** Q/K；旋转后内积只依赖角度差 = 相对距离 |
| ⑤ | 线性层 | 整个 Transformer 只有 y = xW + b 这一种运算 |
| ⑥ | Q/K/V 投影 | 同一份 X 乘三个不同 W，得到 Q/K/V |
| ⑦ | 注意力打分 | S = Q·Kᵀ；**唯一必须是方阵的地方**（行=发问者，列=被关注者） |
| ⑧ | softmax | 分数 → 概率：取 exp、求和、相除；先减最大值是为了不溢出 |
| ⑨ | 加权求和 | O = P·V；把别人的内容按权重搬过来 |
| ⑩ | 多头注意力 | 拆成几份并行算，拼回来再乘 W_O；GQA 为什么 K/V 头更少 |
| ⑪ | 残差 + RMSNorm | 形状必须不变才能「加回去」；归一化把数值拉回稳定量级 |
| ⑫ | FFN / SwiGLU | 升维 → 非线性 → 降维；参数最多的那一块 |
| ⑬ | 堆叠 + 输出头 + 采样 | logits → 温度 → top-p → 抽一个；三种温度的真实概率 |
| ⑭ | 目录全景 | 一个模型文件夹里 10 个文件，分「结构 / 权重 / 文本」三类 |
| ⑮ | config.json | 十几个数字决定全部形状；反推参数量得 6.6B → 「7B」 |
| ⑯ | safetensors 字节布局 | 8 字节长度 + JSON 目录 + 裸数据；比 pickle 安全且快 |
| ⑰ | 分片与 index.json | 按张量切文件；**分片 ≠ 张量并行** |
| ⑱ | 权重名 → 形状 | `[out, in]` 的转置坑、文件里分开而代码里合并的坑 |
| ⑲ | tokenizer 与模板 | 三件套 + chat_template；词表大小必须和 config 对得上 |
| ⑳ | GGUF 与量化 | 分块量化怎么省 3/4 空间；代价是什么 |
| ㉑ | 收尾与索引 | 三张表对齐 + 五步自检 + 全套索引 |

三条阅读路径：

- **只想懂原理**：① → ③ → ⑤ → ⑦ → ⑨ → ⑪ → ⑬
- **想读懂权重文件**：⑭ → ⑮ → ⑯ → ⑰ → ⑱
- **想上手跑模型/调效果**：② → ⑬ → ⑲ → ⑳

## 2. 矩阵示例清单（按你提的三条要求逐条核对）

| 页 | 乘法 | 形状链 | 左矩阵行数 vs 右矩阵列数 | 是否是方阵 |
| --- | --- | --- | --- | --- |
| ⑤ | X·W | 6×4 · 4×5 → 6×5 | 6 ≠ 5 ✓ | 全非方阵 ✓ |
| ⑥ | X·W_Q 等三次 | 5×4 · 4×3 → 5×3 | 5 ≠ 3 ✓ | 全非方阵 ✓ |
| ⑦ | Q·Kᵀ | 5×3 · 3×5 → 5×5 | 5 = 5（**唯一方阵**） | 见下方说明 |
| ⑨ | P·V | 5×5 · 5×3 → 5×3 | 5 ≠ 3 ✓ | 结果非方阵 ✓ |
| ⑩ | 拆头后 Q₀·K₀ᵀ | 5×3 · 3×5 → 5×5 | 同上 | 同上 |
| ⑪ | 层内全链 | 5×6 → 5×6 | — | 无乘法示例 |
| ⑫ | X·W₁ · W₂ | 5×4 · 4×8 → 5×8 · 8×4 → 5×4 | 5 ≠ 8、5 ≠ 4 ✓ | 全非方阵 ✓ |

**关于 ⑦ 的 5×5**：注意力分数天然是「token × token」，行是发问的、列是被看的，
所以它**必然**是方阵。⑦ 页专门用一节解释这一点，并明确写了：
这是全篇唯一必须用方阵的地方，其它页都在刻意避免方阵。

**没有使用 1×2、3×3 这类教学小矩阵**：最小的是 5×3 / 4×3，
最大的是 6×5 / 5×8；示例 token 数 5（⑩ 用 6 维特征）。

## 3. 数字是整数还是小数（每页都标了）

| 东西 | 类型 | 真实模型里 |
| --- | --- | --- |
| token id | 整数 | 整数（0 ~ vocab_size-1） |
| 层号 / 块号 / 形状 | 整数 | 整数 |
| 权重 W | 本页用 0/1/2 | **很小的浮点**（初始化约 ±0.02，fp16/bf16） |
| 激活 X / Q / K / V | 本页用 0~4 的整数 | 浮点（fp16/bf16/fp32） |
| 注意力分数 S | 整数（点积结果） | 浮点 |
| S/√d、softmax 概率 | **小数**（1.73、0.844…） | 浮点，且必须用 fp32 稳定计算 |
| logits / 采样概率 | 小数 | 浮点 |

规则一句话：**整数只出现在「id、下标、形状」，凡是要参与乘加的量和结果都是浮点**。
每页的说明块里都写明了本页数字是"为手算方便故意用的整数"还是"只能是小数"。

## 4. 示例如何对应真实模型

第 ⑤~⑬ 页全程用 **5 个 token × 4 维**（⑩ 用 6 维）演示。换成真实模型只需替换两个数：

| 演示里 | Llama-2-7B | Qwen2.5-7B |
| --- | --- | --- |
| 5 个 token | 你的 token 数 | 你的 token 数 |
| d_model = 4 | 4096 | 3584 |
| d_head = 3 | 128 | 128 |
| ffn = 8 | 11008 | 18944 |
| vocab = 5 个候选 | 32000 | 152064 |
| 32 层 | 32 | 28 |

**形状规则完全不变**，变的只是每一维的数字大小——这正是本套图想让你记住的东西。

## 5. 自查与重生成

```bash
cd assets/vllm-ascend/drawio/tools
python transformer/build.py                     # 重建 21 页成品
python checkdrawio.py ../Transformer与模型文件结构.drawio
python render_check.py ../Transformer与模型文件结构.drawio -o /tmp/r --scale 0.7
python color_audit.py ../Transformer与模型文件结构.drawio
```

配色遵守同目录 `README.md` 的规范，但**语义轴与生命周期那套不同**（已在本套每页的图例里写明）：

| 颜色 | 含义 |
| --- | --- |
| 蓝 | 数据 / 激活（token 向量、张量） |
| 橙 | 权重 / 参数（可训练矩阵） |
| 绿 | 结果 / 新产生的张量 |
| 黄 | 计算动作（乘、softmax、采样） |
| 沙 | 说明 / 结构 / 表格 |
| 红 | 易错点 / 常见误解 |

矩阵格子的颜色也遵守这套语义：X 蓝、W 橙、结果绿——**看一眼颜色就知道哪个是要被乘的、哪个是乘出来的**。

## 6. 数字的正确性怎么保证

运行示例不是手写的，而是 `tools/transformer/ex.py` 里算出来的（`mm()` 做矩阵乘，页面直接引用结果）。
所以：

- ⑤ 的 R、⑥ 的 Q/K/V、⑦ 的 S、⑧ 的 P、⑨ 的 O、⑫ 的 H 全部**自洽**，
  手算任何一格都能对上；
- ⑧ 的 softmax、⑬ 的三种温度概率，也是代码算的（`math.exp`），不是估的；
- ⑪ 的 RMSNorm 例子特意选了 `[3,4,0,0]`（均方 6.25、RMS 2.5），因为能整除，方便你复算。

想验证：`python -c "import ex; print(ex.S)"`（在 `tools/transformer/` 目录下）。
