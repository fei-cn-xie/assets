## 1. v1 计划诊断：7 个具体问题

### ✅ 合理的部分（保留）

- **能力链方向正确**：看懂模型 → 看懂框架 → 看懂硬件 → 理解算子 → 分析性能 → 独立优化。这条链是对的。
- **目标硬件明确**：绑定 A2/A3，没有盲目追 CUDA，这个判断很专业。
- **有交付物意识**：每个阶段都写了产出物，比"看完某本书"强得多。
- **强调不脱离工作、要有输出**：这是全部计划里最有价值的两条原则。
- **ITL 五层排查法**（请求/调度/框架/算子/硬件）是真实有效的工程方法论，可以直接用。

### ❌ 不合理或不适配的部分

**问题 1：起点假设与你的实际水平差了两档，但没有降级机制**
v1 第 4～6 周就要求 C++（模板、内存模型、原子操作）+ PyTorch Dispatcher + 自定义算子。而你的实际状态是：Python 偏脚本层、Attention 的 QKV 讲不清、vLLM 只能改局部模块。这条路径会在第 5 周直接卡死，然后产生"我不适合做 infra"的错误结论。
→ **不是你不适合，是计划跳步了。**

**问题 2：开局三周是低回报前置**
操作系统内核、网络 TCP/HTTP/2、RPC……这些对最终能力有用，但对"半年内做出可讲项目"几乎零贡献，且最容易变成"读了很多、什么都做不出来"的开始。
→ 这类知识应该**按需触发**：遇到 CPU 打满再学调度，遇到通信瓶颈再学 RDMA。v1 自己也写了"按需"，但正文却给了固定 3 周，自相矛盾。

**问题 3：把最强资源（真机）排到了第 15 周**
你有 A2/A3 真机 + Profiling 权限 + 三种真实业务场景（性能排查/模型适配/改调度）。这是 90% 自学者拿不到的条件。v1 却让你先学 10 周理论才碰设备。
→ **顺序完全反了。** 应该第 1 周就建立基线数据，让后面每一周的理论都能挂在真实数据上。

**问题 4：26 周 × 8~10h = 208~260h，试图覆盖 7 大块**
算上你的实际时间是 14h/周 → 364h。但即使 364h 也**不足以**让 C++、算子开发、编译器、vLLM 源码任何一项达到"独立开发"水平。v1 的问题是**没写清楚哪些到 L1（懂）、哪些要到 L3（能优化）**。
→ 必须分层：核心 20% 打到 L3，支撑 50% 打到 L2，外围 30% 只到 L1。

**问题 5：没有"可面试"里程碑，只有"学完"里程碑**
求职不是学完才发生的事。第 8 周还没有能讲的项目，后面会陷入"再学一点就去投"的无限推迟。
→ 倒排：**第 8 周项目一落地，第 12 周项目二落地，第 14 周简历定稿。**

**问题 6：算子开发被当成必选项，但对你的岗位不是**
你日常是"改框架、查性能、适配模型"，不是写高性能 kernel。独立开发一个达到商用水平的 NPU 算子，对 4 年经验的转型者来说投入产出比很低（C++ + 汇编 + 编译器 + 架构，每一项都要年为单位）。
→ 算子能力只需要到：**看得懂调用栈、能替换/适配一个简单算子、能做精度与性能验证**。这条已经足够支撑面试"你了解算子吗"的问题。

**问题 7：薪资目标与时间线没有对齐**
深圳 AI Infra 推理优化岗 25~30K，通常对应 3~5 年相关深度 + 有量化结果的优化项目；成都同岗位普遍低 10~20%，25~30K 在成都属于较高区间。你 2022 年本科毕业（约 4 年经验），**这个目标不虚，但必须以"有数据的项目"为支点**，否则 4 年经验 + 二开经历很难跨过 25K。

### 补充：一个直接的排版问题
文件实际路径是 `assets/learn/`，不是 `asstes/learn/`。建议顺手修正，避免以后自己找不到。

## 4. 重构后的路线：三条泳道

时间占比：**主线 50% / 支撑 30% / 底层 20%**。

### 泳道 A（主线，50%）：vLLM 推理链路与性能优化

| 周 | 内容 | 验收（L 级） |
|---|---|---|
| W1 | 环境盘点、跑通基线、建仓库 | L2 能复现基线数字 |
| W4 | vLLM 版本对应的真实架构图（Engine/EngineCore/Scheduler/Worker/ModelRunner） | L1 能画出模块关系 |
| W5 | 请求调用链：HTTP → tokenize → schedule → execute → sample → detokenize | L1 能报出关键类与函数 |
| W6 | Scheduler：waiting/running/victim 队列、token budget、preemption | L2 能通过日志复现一次抢占 |
| W7 | KV Cache：BlockPool、BlockTable、prefix caching、碎片 | L2 能算出占用并解释 OOM 原因 |
| W8~W11 | Profiling 五层法 + 项目二优化 | L3 有 A/B 数据 |
| W12~W14 | 项目包装、简历、八股 | L3 能讲 45 分钟 |

### 泳道 B（支撑，30%）：模型原理 + 张量 + PyTorch 机制

| 周 | 内容 | 验收 |
|---|---|---|
| W2 | Attention 数学与 Shape 推导（含 GQA/MQA） | L1 白板推导 QK^T、softmax、AV 的形状 |
| W2 | RoPE、RMSNorm/LayerNorm、SwiGLU、残差 | L1 能写出公式与计算量 |
| W3 | Prefill vs Decode 的定量差异（roofline） | L1 能用公式说明为什么 decode 带宽受限 |
| W3 | KV Cache 显存公式 + VLM 的图像 token 流 | L2 能对真实模型算出显存占用 |
| W3 | VLM 结构：ViT → patch → projector → LLM | L1 能讲清图像如何变成 token |
| 贯穿 | PyTorch：Tensor/stride、autograd、module hook、dispatch、torch.compile | L1 能解释 `model(x)` 背后发生了什么 |

### 泳道 C（底层，20%）：NPU / 算子 / C++（按需触发，不做整块前置）

| 时间 | 内容 | 触发条件 |
|---|---|---|
| W1 起，每周 1~1.5h | C++ 子集：指针/引用、RAII、智能指针、STL、类与虚函数、`std::thread` | 读 vLLM C++/算子代码遇到就看 |
| W5~W7 | NPU 执行模型：device/stream、H2D/D2H 拷贝、算子下发、同步点 | 追链路时必然遇到 |
| W9~W11 | 内存层次、HBM 带宽、算力单位换算（TOPS/TFLOPS） | 做 roofline 分析时 |
| W19~W22 | 算子调用栈 + 一个简单算子（RMSNorm/RoPE）适配与验证 | 项目三 |
| 按需 | OS/网络：进程线程、perf/strace、TCP、序列化 | 排查卡住时再补，不做整块学习 |

### 明确砍掉 / 降级的内容

| 内容 | 处理 | 理由 |
|---|---|---|
| CUDA Kernel 开发 | **不学**，只保留 roofline 与并行概念 | 目标硬件非 NVIDIA |
| vLLM 全量源码 | **只读核心链路** 5~7 个文件 | 全读是几万行，收益递减 |
| C++ 完整语言体系 | **只学子集**，不追模板元编程/内存模型细节 | 你的岗位不需要写框架 |
| 编译器理论（词法/语法/IR 全链路） | **降到 L1**，只懂"算子如何变成 kernel" | 半年不够 |
| 网络/RPC 深入 | **降到 L1**，懂一次请求的网络环节即可 | 低回报前置 |
| 高性能算子调优（tiling/pipeline/双缓冲） | **了解即可**，不做实践 | 投入产出比低 |

## 6. 三级验收标准（替代打勾清单）

| 等级 | 含义 | 检验方式 |
|---|---|---|
| **L1 能解释** | 不查资料，白板/口述讲清楚 | 对着手机录音讲 3 分钟，回放能听懂 |
| **L2 能复现** | 能在真机跑出结果，脚本别人能重跑 | 仓库里有脚本 + README + 输出数据 |
| **L3 能优化** | 能定位瓶颈、给出方案、有 A/B 数据、讲清 trade-off | 报告里有"优化前/后"对比表和结论 |

**各阶段最低要求：**

- 模型原理（W2-W3）：L1 全部 + KV Cache 计算 L2
- vLLM 链路（W4-W7）：L1 全部 + 至少 2 个模块 L2
- Profiling 与优化（W8-W14）：**L3**（这是你的核心卖点）
- NPU / 算子（W19-W22）：L1 全部 + 一个算子 L2

> 判断"学会了"的唯一标准：**能不能在没人提示的情况下，从问题推到结论。**

## 7. 三个项目（简历级）

### 项目一（W4~W7）：VLM 请求全链路追踪与耗时拆解

- **问题**：一次 VLM 请求（含图像）从进来到出 token，时间花在哪？
- **动作**：选一个实际模型，固定输入，用 trace + 埋点 + 日志，把耗时拆到模块级（排队/tokenize/vision encoder/prefill/decode/sample/detokenize）。
- **产出**：架构图 + 关键函数表 + 耗时饼图 + "哪一段最值得优化"的结论。
- **面试价值**：证明你真的读懂了框架，不是只会调用。

### 项目二（W8~W12）：某场景 TTFT / ITL 波动的定位与优化

- **问题**：真实业务里 TTFT 或 ITL 出现长尾/波动。
- **动作**：五层排查法逐层排除；用数据证明瓶颈层；给出 1~2 个优化（如调度参数、批处理策略、前缀缓存、去同步、拷贝消除）。
- **产出**：问题 → 数据 → 定位 → 方案 → A/B 对比 → 局限。
- **面试价值**：**这是最值钱的一个项目**，直接对应 25K+ 岗位的核心要求。

### 项目三（W19~W22）：简单算子（RMSNorm）适配与验证

- **动作**：PyTorch reference → 目标 NPU 实现/替换 → 精度对比（误差阈值）→ 性能 benchmark → 结论。
- **产出**：数学定义 + 接口 + 实现 + 精度表 + 性能数据。
- **面试价值**：证明你不只会用框架，能下沉到算子层。

> 三个项目覆盖了面试官最常问的三层：**框架层、系统层、算子层。**

### 简历叙事模板（每个项目 5 句）

```text
背景：什么场景、什么规模、什么指标异常
问题：具体现象 + 量化（如 ITL P99 从 40ms 涨到 120ms）
动作：你做了什么（排查路径 + 关键实验 + 你的判断）
结果：优化后数字（P99 降到 55ms，吞吐 +18%）
反思：trade-off 是什么、还有什么没解决
```

### 9.2 基线压测（固定 workload，可重跑）

```python
# bench_vllm.py —— 通过 OpenAI 兼容接口测 TTFT / ITL / 吞吐
import time, statistics, argparse
from concurrent.futures import ThreadPoolExecutor
from openai import OpenAI

def one_request(client, model, prompt, max_tokens):
    t0 = time.perf_counter()
    first, chunks = None, 0
    stream = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        max_tokens=max_tokens, temperature=0, stream=True,
    )
    for _ in stream:
        chunks += 1
        if first is None:
            first = time.perf_counter() - t0
    total = time.perf_counter() - t0
    return {"ttft": first, "total": total, "tokens": chunks}

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--base-url", default="http://127.0.0.1:8000/v1")
    ap.add_argument("--model", required=True)
    ap.add_argument("--concurrency", type=int, default=8)
    ap.add_argument("--requests", type=int, default=32)
    ap.add_argument("--max-tokens", type=int, default=256)
    ap.add_argument("--prompt", default="请用 200 字介绍深度学习推理优化。")
    a = ap.parse_args()

    client = OpenAI(base_url=a.base_url, api_key="EMPTY")
    with ThreadPoolExecutor(a.concurrency) as ex:
        rs = list(ex.map(lambda _: one_request(client, a.model, a.prompt, a.max_tokens),
                         range(a.requests)))
    ttfts = sorted(r["ttft"] for r in rs)
    totals = [r["total"] for r in rs]
    toks = sum(r["tokens"] for r in rs)
    p = lambda xs, q: xs[min(len(xs) - 1, int(len(xs) * q))]
    print(f"requests={a.requests} concurrency={a.concurrency}")
    print(f"TTFT  p50={p(ttfts,.5):.3f}s p90={p(ttfts,.9):.3f}s p99={p(ttfts,.99):.3f}s")
    print(f"E2E   mean={statistics.mean(totals):.3f}s  max={max(totals):.3f}s")
    print(f"tokens={toks}  throughput={toks / sum(totals):.2f} tok/s(avg)")

if __name__ == "__main__":
    main()
```

用法：`python bench_vllm.py --model <你的模型名> --concurrency 8 --requests 32`
**每周同一组参数重跑，形成趋势表** —— 这张表本身就是简历素材。

### 9.3 KV Cache 显存估算练习（W3 用）

```python
def kv_cache_gb(layers, kv_heads, head_dim, seq_len, batch, bytes_per=2):
    """GQA/MQA 下的 KV Cache 大小（GB）。bytes_per：fp16=2, int8=1"""
    b = 2 * layers * kv_heads * head_dim * seq_len * batch * bytes_per
    return b / 1024**3

# 示例：28 层、4 个 KV head、head_dim=128、fp16、单请求 8K 上下文
print(kv_cache_gb(28, 4, 128, 8192, 1))                 # 单请求
print(kv_cache_gb(28, 4, 128, 8192, 1) * 32)            # 32 并发
print(kv_cache_gb(28, 4, 128, 8192, 1) * 32 * 0.7)      # 实际可用（留余量）
```

**练习目标**：给定自己线上的模型配置，算出"理论上最多能同时跑几个 8K 请求"，再去真机验证。**算的和实测对不上，就是最好的学习入口。**

## 10. 学习方法（针对你的短板定制）

### 10.1 读源码：五步法

```text
1. 从入口进：先找 API handler，不看实现细节
2. 只追一条路径：一个最简单的请求（batch=1, 短 prompt）
3. 打断点/加日志：让代码告诉你顺序，而不是你猜
4. 画图：每追一层画一个框，画不出就是没懂
5. 再读实现：这时才看算法细节，效率高 10 倍
```

**纪律**：一次只追一条路径。看到不相关的分支就记下文件行号跳过——**"待读清单"比"当场读懂的执念"更重要**。

### 10.2 费曼检验（每周 5 分钟）

对手机录音讲 3 分钟：这周学了什么、解决了什么问题、还有什么不懂。回放时卡壳的地方就是没懂的地方。**这一步能筛掉 80% 的"假懂"。**

### 10.3 实验设计三原则

1. **先基线**：任何优化前先记录现状数字。
2. **单变量**：一次只改一个东西，否则结果无法归因。
3. **可重跑**：命令写进脚本，参数写进 README。别人的机器能跑出同样结论。

### 10.4 笔记格式：一个问题一页

```markdown
## 问题：并发 8→16 时 ITL 为何翻倍？

- 现象：（数据）
- 假设 1：（依据）→ 验证方式 → 结果 → 排除/成立
- 假设 2：……
- 结论：
- 遗留：
```

> 半年后你会积累 40~60 个这样的页面，**这就是面试题库和简历素材库**。

### 10.5 三条纪律（比方法更重要）

1. **一次只开一个方向**：这周说 vLLM 就只碰 vLLM，别同时开 C++ 和编译器。
2. **学完 24 小时内必须有产出**：笔记/代码/图，三者之一。
